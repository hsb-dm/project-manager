# ZenCrevia v17 — implementation of the v17 audit backlog

Built from `ZenCrevia_AI_Hub_V2_Optimization_UI_Revamp_v19.md` against standalone v16.
Everything below was edited in `src/` and `server/`; `dist/creative-os-standalone.html`
and `public/index.html` are regenerated by `node build.js`.

## P0 — correctness

**P0-1 · Tags have no colours.** Removed `TAG_COLORS`, `tagAutoColor()`, `tagColorCss()`,
`setTagColor()` and the `.tag-dot` element. Tags render as one neutral pill; selection uses
border + `--color-primary-soft`. Legacy `{name,color}` records and plain strings are still
read, the colour is ignored, and it is stripped on the next normalised save. Workflow, Team
and Label colours are untouched.

**P0-2 · One `addTag()`.** The older string-based `addTag()` that shadowed the newer one at
runtime is deleted. `createWorkspaceTag()` in `tag-picker.js` is now the only creation path —
Settings → Tags, the picker's "Create new", and any future inline creation all call it.

**P0-3 · Global tag picker everywhere.** Converted `ep_tags`, `np_tags`, `agTags`,
`agEditTags`, `ua_tags`, `lc_tags`, `as_tags` and the Grid view's tag cell from free text to
the shared picker. `tagPickerValues()` reads a picker at submit; no code splits a comma
string into tags any more.

**P0-4 · Tags drag-and-drop.** Tags register with the existing `registerReorderList()` engine
(no second drag system). `sortOrder` persists client- and server-side, the picker follows the
manual order, and a kebab menu provides Move up / down / to top / to bottom.

**P0-5 · External AI recommendations are actually external.** The old flow could label advice
"your configured AI provider" while the deterministic local rules produced it. Now
`resolveReportRecommendations()` makes a real provider call, validates that the response parses
into the requested structure, and only then applies the external label naming the registered
model. Any failure — unreachable, timeout, unparseable, empty — falls back to the internal
engine with the internal label and never blocks the export.

**P0-6 · One AI policy.** `DEFAULT_AI_POLICY`, `effectiveAiPolicy()`, `aiCanAddLayers()` and
`aiCanAddImageLayers()` in `src/ai-policy.js`. Every add-layer path is guarded through it.
The business-rule `100` is gone from add / paste / duplicate / gallery normalise; a separate
`AI_SAFETY_CEILING` remains as a system limit only.

**P0-7 · Admin-configurable history retention.** `slice(0,24)` replaced by `aiTrimHistory()`.
Users see `18 / 24` and an "At capacity" badge. Trimming touches History only — never Gallery
or Assets.

**P0-8 · AI Gallery quotas.** Total, per-day-new and per-day-duplicate limits, configurable by
an admin and visible to the member in the gallery header and the save dialog. At full quota
view / edit / download / favourite / archive / delete stay available; only new, save-as-new
and duplicate are blocked.

## P1

**P1-1 · Admin model registry.** `src/ai-admin.js` holds the one registry: display name, model
ID, provider, active, default, capabilities, drag order. Users pick a display name — the
"Custom model ID" field and the hardcoded `<optgroup>` list are gone. Requests carry
`modelRegistryId`; the server resolves the real model and refuses any ID that is not
registered and active.

**P1-3 · AI settings IA.** AI & Integrations is now Overview / Models / Usage & Limits /
Providers / Permissions / Data & Privacy.

**P1-4 · SMTP in the Admin dashboard.** Seven-step guided flow with provider presets
(Google Workspace, Microsoft 365, Amazon SES, SendGrid, Mailgun, Zoho, Custom), host / port /
encryption / credentials / sender / reply-to, a real "Test connection" that negotiates TLS and
authenticates without sending, a "Send test email" that can exercise unsaved settings, and a
delivery log. Credentials are encrypted server-side and never returned after save. Environment
variables still work as the fallback.

**P1-5 · Backup History, restore and rollback.** Backups now carry a sidecar with SHA-256
checksum, creator, reason and integrity result. Backup & Data is Overview / Backup History /
Import-Export / Automatic Backups / Retention / Storage. A restore verifies the checksum
first, takes a pre-restore safety backup, stages and validates the file before replacing
anything, and rolls the previous database back on failure. Every restore is written to an
audit trail. Safety copies are exempt from retention pruning.

**P1-6 · Correct per-person asset attribution.** Assets are credited from real creator
metadata — `version.createdBy` → `asset.createdBy` → `producedByUserId` — and only fall back
to apportioning across task assignees when nothing is recorded. A fallback figure is labelled
"Assets produced (attributed)" with a footnote, so an approximation never reads as a
measurement.

**P1-7 · Admin settings UX.** Applied inside the areas that were actually hard to read —
AI & Integrations and Backup & Data are now sub-navigated areas with an overview page, plain
language, helper text and recommended defaults. The top-level Settings navigation stays a
single flat tab list: grouping it into labelled categories was tried and reverted, because the
category headers added visual noise to the sidebar without making anything easier to find.

## P2

- **P2-1** Drag reorder extended to Custom fields, Brief templates and AI models.
- **P2-2** Export UI counts "report sections", not physical slides.
- **P2-3** Production storage guidance surfaced in Backup → Storage.
- **P2-4** `aiPropertyChanged()` — routine property edits refresh the inspector and redraw the
  canvas instead of rebuilding the whole AI Hub. Structural re-render is kept for add/delete
  layer, load document and template switch.

## §18 / §20 — Task gear

A dedicated gear (`data-tour="task-settings"`) in the Task Detail and New Task header opens
Panel position: Right / Center / Left, as `role="menuitemradio"` rows with full keyboard
support. It reads and writes the **existing** `myPrefs().taskPanelPosition` through the same
`taskPanelPosition()` / `setTaskPanelPosition()` functions Settings uses, so the two can never
disagree — changing it in Settings repaints an open gear menu and vice versa. Switching
position never rebuilds the drawer: the open task, its tab, drafts and unsaved edits all
survive. Workspace Quest gained a `personal.taskPanel` step that highlights the gear inside a
task and no longer routes the tutorial through Settings → Layout.

## Data model / schema

- `tags` gains `sort_order` and `archived` (and deliberately no colour column).
- `workspaces` gains `smtp_settings` and `backup_settings`.
- All four are additive migrations in `server/db.js`; existing databases upgrade in place.

## Verification

- `npm test` — 71 tests, including new coverage for backup create/verify/restore/rollback,
  corrupt-backup refusal, retention exemptions, SMTP round-trip and encryption at rest, and
  server-side model registry enforcement.
- A headless Chromium suite of 41 checks over the built standalone: tag colour removal,
  canonical `addTag`, reorder, legacy tolerance, the AI policy and quotas, the registry,
  the truthful AI source label, asset attribution, the task gear, the new admin areas, plus
  regressions over every screen, every task view, and the PPTX and XLSX exports.
- A live server run: SMTP save/encrypt, backup create → verify → restore → rollback, corrupt
  backup refused with the database untouched, and the audit trail.

# v17.1 — AI Hub Properties revamp and admin UI corrections

## Settings navigation
Reverted the category grouping (it added visual noise to the sidebar without
helping anyone find anything). The 17 tabs are one flat list again, **reordered**
so neighbours belong together: personal → workspace identity → task shape →
taxonomy → people → systems.

## Admin UI corrections
- **Status pills were unreadable.** `.pref .pl span` (specificity 0,2,1) was
  overriding `.badge.approved` (0,2,0), so "Active" rendered grey-on-green.
  Every badge variant now restores its own foreground at matching specificity.
- **Checkbox rows in dialogs were broken.** A `<label class="chipx">` nested
  inside a `.field` inherited `display:block` and `text-transform:uppercase`
  from `.field label`, which pushed the box above an all-caps label. Replaced
  with a proper `.check-list` component: control on the left, title and
  explanation stacked beside it, consistent 9×12 padding, hover and checked
  states.
- **Default model is a dropdown** (§6.4). It lists the registry and writes
  through the same "make default" path as the Models tab, so a default can no
  longer be a hand-typed model ID that the registry would reject.

## AI Hub Properties — rebuilt (v16 §11–§33, v17 §P1-2)
The old panel was a single string builder whose output three other files
re-parsed and re-grouped by regex-matching English label text — a renamed label
silently moved a control to the wrong section. `src/ai-properties.js` replaces
the property body with a real object inspector. The Layer panel is untouched
(§34).

- **Font size in real pixels** (§22). Extra text layers store px directly;
  built-in layers store a percentage scale, so an adapter converts against the
  size the renderer derives (§18) — no renderer migration, and the UI never
  shows "Size (%)" again.
- **px / % for X, Y, W and H** (§17) with one contextual unit switch in the
  Transform header. Switching never moves the layer.
- **Icon-first controls** (§15) with an alignment toolbar (§33); every
  icon-only control carries both a tooltip and an aria-label (§72).
- **Selected-layer header** (§13) with visibility, lock, duplicate and delete —
  no longer buried at the bottom of the panel.
- **Section order declared per layer type** (§29) — text, image, shape and
  canvas each get their own set, in the documented order.
- **One control system** (§14): a single height, gap and radius token set; no
  control sets its own inline padding.
- Collapsible sections with persisted state (§31), multi-selection showing only
  shared properties (§32), and a proper empty state (§76).
- Internal field names (`textX`, `offsetUnit`, `layerScale`) no longer appear
  anywhere in the panel (§71).

## Remaining v16 items now applied
- **§8 hard safety caps.** `SYSTEM_AI_LIMITS` plus
  `effectiveLimit = min(workspace, system)`. An admin can lower any limit but
  can never raise it past what the client survives.
- **§9 layer counter** on the Layers panel, with an 80% warning tone and the add
  buttons disabled at the limit.
- **§43 capability-driven UI.** The registry's capability flags now do something:
  a model without `reference` disables the reference-image control and says why,
  instead of the request being silently ignored at generate time.
- **§44 Generate states.** No active model, or no provider configured, disables
  Generate with the reason shown inline as well as in the tooltip.
- **§46** canvas maximum, per-design size ceiling, and "archived designs count
  toward the quota".
- **§47 resource usage** on the AI overview, with estimates labelled as such.
- **§48/§49/§80 dedicated AI Gallery permissions** — `use_ai_hub`,
  `view_ai_gallery`, `publish_ai_gallery`, `duplicate_ai_gallery`,
  `manage_own_ai_gallery`, `manage_all_ai_gallery`. Publishing to the shared
  Gallery no longer rides on `upload_file`, which meant anyone who could attach
  a file to a task could publish. Legacy roles keep working through a documented
  fallback.
- **§53 legacy over-limit designs** open, edit, reorder, delete, export and save
  normally; only additions are paused, and the message says so rather than
  implying the design is broken.

## Verification
73 unit tests (up from 71) and two headless Chromium suites — 41 checks on the
v17 behaviour plus 17 on the Properties panel, covering section order per layer
type, the px font-size adapter in both directions, unit switching not moving the
layer, uniform control heights, header quick actions, capability-driven controls,
Generate states, and that a routine property edit never calls `renderScreen`.

# v17.2 — UI corrections

1. **Calendar day sheet** — the right-hand metadata was a wrapping flex row, so
   each task's chips landed at a different x depending on what that task had.
   Labels moved onto the meta line beside team and project (where they read as
   what they are and can wrap freely), and the remaining three slots — assets,
   due, assignee — became fixed grid columns on a fixed-width track. Every row
   now aligns on the same columns; verified by measuring column positions.
2. **PPT text over shapes** — the slide note was hard-placed at y=6.62, which is
   *inside* the per-person card (it runs to 6.9), so the text rendered on top of
   it. Notes now go through a `footNote()` helper that measures how many lines
   the text wraps to and anchors above the "ZenCrevia · date" footer band at
   7.05. The AI-recommendations list had the same class of bug — it advanced a
   fixed 0.95in per item regardless of whether the detail wrapped — so rows now
   advance by their measured height.
3. **PPT per-person figures** get the same tinted stat cards as the headline
   metrics slide. "(attributed)" became a `*` marker explained in the slide note,
   because the long form wrapped badly in a narrow card.
4. **Task menu** — the header had two near-identical icon buttons. They are one
   menu now: the three panel positions as icons in a row (left | centre | right)
   with the route to full layout settings beside them, a divider, then the task
   actions (duplicate, export, hide, delete). Arrow keys walk the row in both
   axes.
5. **Checkbox capsules** — `.field label` (0,1,1) was overriding `.chipx` and
   `.report-slide-chip` (0,1,0), killing their flex layout and forcing
   UPPERCASE, so the box stacked above an all-caps label. One shared spec now
   covers every capsule: control, 8px gap, label, 7/13 padding, 34px min height.
   The duplicate older spec was deleted rather than left to compete.
6. **"Automation & auto-hide" → "Automation"** so the sidebar item fits one line.
7. **Language switch** no longer calls `closePops()`, so the menu stays open and
   translates in place instead of vanishing mid-click; it is re-anchored after
   the re-render.
8. **AI Gallery** hides "View all gallery designs" on the All designs tab, where
   it would only reload the same empty list. It still appears on a filtered tab
   or an empty search, which is where it actually helps.

Verified with the existing suites plus a rendered check of the deck: the PPTX is
converted to PDF and every page scanned for text whose bounding boxes intersect —
currently zero across all 14 slides.

# v17.3 — Print / Save-as-PDF, and one AI setup notice

## Print / PDF was broken
"Print / PDF" calls `window.print()`, but the only print rule in the app hid the
top bar. Everything else printed as-is, so the output was unusable:

- **content was clipped at the right edge** — the app is a wide, horizontally
  scrolling layout and the page is portrait, so the kanban board and the
  pipeline row were cut off mid-column;
- **screen chrome printed** — the mobile bottom tab bar, the floating AI button,
  the per-card "half width / minimize / hide" controls, view switchers, sort,
  filters, "New task", "+ Add task", "View all";
- **empty kanban columns** printed as tall blank boxes, padding the document out
  over several pages.

There is now a real print stylesheet: fixed-height scroll panes release their
height, wide layouts reflow (the board stacks, grids drop to two columns, tables
go full width and wrap), every interactive control is hidden while badges and
chips — which are content — are kept, cards and rows get `break-inside: avoid`
so nothing splits across a page, and the deck prints on white with light colours.

Verified across all eight screens by generating the PDF and checking two things
programmatically: that no known chrome element has a client rect in print media,
and that no text runs past the page's right edge. Currently clean on all eight.

## One AI setup notice
AI Hub showed two banners saying the same thing — the generate-state reason and
the older "add an image API key" prompt. They are one card now. The headline is
the specific reason ("Image generation is not connected yet." / "No image model
is active yet."), the button goes to the section that fixes that particular
problem (Providers or Models), and the full path is kept only in the Generate
button's tooltip, where there is no button to follow.

# v17.4 — Task menu, onboarding placement, AI-panel step

1. **Task settings menu was broken.** `.menu button{width:100%}` (0,1,1) beat
   `.gear-pos` (0,1,0), so each position icon stretched to the full menu width
   and spilled out of the panel — 375px per icon in a 407px menu. The same
   specificity trap as `.field label` over `.chipx`. Selectors now match that
   specificity, the icons are square again, and the menu is tightened to 210px
   (shorter helper text, tighter padding).
2. **Panel-position tutorial moved to step 8**, inside the Task workflow
   chapter, where the practice task is already open — instead of at the end of
   the quest where it had to open a task of its own. Renaming it `workflow.*`
   means `wqPrepare` opens the practice task for it, so the bespoke branch added
   for it earlier could be deleted.
   Two defects came out of this: the step was missing its 9th field (the
   "DO THIS" line), which crashed `wqRenderCoach` with
   `Cannot read properties of undefined`; and adding it had pushed the quest to
   102 XP, so progress reached 100% before the last step. Both fixed — every
   step is now a well-formed 9-field entry and the quest totals exactly 100.
3. **"Close the AI panel" step was uncompletable.** The task drawer is opened by
   the workflow chapter and nothing closed it on the way into the AI chapter, so
   the AI panel opened *behind* the drawer's overlay: the close button existed
   but was covered, the spotlight landed on nothing, and the step sat on
   "Waiting…" forever. The AI steps now close the drawer first.
4. **Print / PDF** — the click and `window.print()` were always firing; what was
   broken was the output, fixed in v17.3. Re-verified from the states a user
   actually prints from, including with that export menu open.

Verified by rendering every one of the 23 quest steps' coach cards and checking
that each spotlight target exists and is the topmost element at its own centre —
a check that would have caught the missing-field crash immediately.
